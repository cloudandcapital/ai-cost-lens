How this number is built

Full recurring cost = provider spend + shared infrastructure included in the review + human review and correction.

Cost per ready result = full recurring cost ÷ results that met the quality bar.

Observed logs, samples, estimates, and missing evidence remain visibly different. A sampled or user-estimated result cannot become proven savings.

For an invoice or subscription, enter one row with period=baseline, the invoice date in date (YYYY-MM-DD), the subscription or workload name in workload, the billed amount in provider_cost, cost_basis=provider_reported, and a three-letter currency. Enter provider if known. Leave model, route, requests and tokens blank unless the source supports them. An invoice date is not evidence of the service-period duration.

With usage, transfer matched date/workload/model/route buckets into separate rows: provider, model, route, requests, input_tokens, cached_input_tokens, cache_write_input_tokens, and output_tokens. Input tokens include uncached, cache-read and cache-write tokens. Requests include retries. Blank means unknown; zero means a confirmed zero.

Each cost amount must appear once. If cost cannot be joined to model-level usage, aggregate usage to the bill boundary in one row and leave model/route blank; do not spread dollars by token share. Use calculated for quantity × rate or allocated for a documented share of a bill, never label those billed evidence. Keep one currency, workload and cost basis per review.

Only this completed CSV template is supported here. Manually transfer the supported fields from your source; PDFs, screenshots and arbitrary raw provider exports are not automatically read.

Show me exactly what to put in each column
periodbaseline or proposed.
dateThe date of that report bucket in YYYY-MM-DD format. Keep provider cost and usage grouped the same way.
workloadYour plain language name for the work. Use the exact same name on both routes.
providerThe company or platform that served the model, such as Anthropic, AWS Bedrock, Google Cloud, OpenAI, or your gateway.
modelThe reported model name. Use “Mixed models” only when the source report does not support a reliable model split.
routeYour label for how the work ran, such as “Current production route” or “Proposed pilot route.”
requestsEvery provider call in the bucket, including additional attempts. Use application or gateway logs when the provider report omits it. Otherwise leave blank.
input_tokensAll processed input tokens. When a provider splits uncached, cache read, and cache write tokens, add those parts here and keep the cache columns too. Leave blank if unavailable.
cached_input_tokensInput tokens read from cache. Enter 0 only when the report confirms none; otherwise leave blank.
cache_write_input_tokensInput tokens written to cache. Enter 0 only when the field is reported as zero or does not apply; otherwise leave blank.
output_tokensAll output tokens. Leave blank if the source does not report them.
provider_costThe cost for this row. Do not repeat one invoice total across several model rows.
cost_basisprovider_reported for a billed amount, calculated for quantity × rate, or allocated when you assigned part of a shared bill.
currencyA three-letter code such as USD. Both routes must use the same currency.
Before you upload it
  • Both routes describe the same workload and use the same currency.
  • Each source amount appears once. Do not copy one invoice total onto every usage row.
  • Blank means the source did not supply the measure. Zero means the source reported zero or the measure does not apply.
  • The upload cannot read raw Anthropic JSON, AWS CUR files, Google billing exports, PDFs, or screenshots directly.

Add what happened to the work

Use the same definition of “ready” for both routes and classify each result at the end of the review. A quick sample gives you a clearly labeled estimate; a complete work log supports a stronger review.

One result is one unit of finished work, such as one reviewed summary, extracted invoice, resolved case, or completed task. It is not one API request. One result may require several model calls.

Ready to useThe result cleared your rule, including after any correction you completed. Include all time spent.
Needs correctionThe result has not cleared the rule and still needs material work.
Needs escalationThe result could not be completed through the normal review path.
Use the same quality rule on both routes. Enter the number of outputs in the period, then what you found in the reviewed sample.
