## Confirmed findings and corrections

| Finding | Correction and evidence |
| --- | --- |
| JavaScript accepted rollover calendar dates | UTC round-trip date validation rejects February 31, non-leap February 29, April 31, and invalid month values. OpenAI time buckets also validate calendar dates and timestamp ordering. Python already used `date.fromisoformat`. |
| Unequal period totals could be compared | Both browser comparison modes and the Python manifest builder reject unequal inclusive date spans. Newly built route records retain their own start/end dates. Guidance requires equally long, complete periods; observed row dates alone do not prove coverage. No implicit normalization is performed. |
| Saved review validation was shallow | Recursive typed validation checks required nested objects, arrays, booleans, strings, finite numbers, dates, rates, cost reconciliation, outcome counts, comparison cost basis, and savings gates. Optional planning and sampled sections are validated when present. Invalid input restores the previous valid review and reports a readable error. The regression check removes 127 required fields individually. |
| CSV input had no bounds | Files are limited to 5 MiB; CSV files are limited to 20,000 data rows. File size is checked before reading an uploaded file. Limits and remedies are visible before import. |
| Adjustments were insufficiently explained | Negative cost rows are rejected with a credit/refund-specific message. Users must reconcile credits and refunds to a non-negative cost in the source and keep the same workload, period, and gross/net treatment. Documented discounts are included in the supplied non-negative cost. No adjustments are silently omitted or allocated. |
| Identical spend rows could double-count | Exact normalized duplicate spend/usage/cost rows are rejected with the row number. Nothing is silently deduplicated. Genuinely separate identical charges must be checked and consolidated in the source. Duplicate result IDs remain rejected. |
| Lumen boundary needed explicit wording | Both the entry point and dialog state that Lumen is deterministic, uses only the calculated review, and does not contact an AI API. Its conversation is cleared when a different review renders. |
| Sharing metadata and favicon were absent | Added branded canonical URL, Open Graph title/description/URL/image/alt/dimensions, large-image card metadata, and SVG favicon. The social image is the existing approved cost-anatomy screenshot, unchanged. LinkedIn can consume Open Graph metadata after a production release; its live scraper has not been tested against this private candidate. |
| Wordmark destination was wrong | Cloud & Capital wordmarks now link to `https://cloudandcapital.com`, including the secondary model-route pages. |

## Single-bill requirement

Confirmed: the pre-change universal browser path required both baseline and proposed spend and outcomes. Added a separate **Review one bill** choice, reusing the existing dialog, bill layout and templates. No stylesheet, provider calculation or comparison gate was redesigned.

| Evidence supplied | Behavior |
| --- | --- |
| Invoice/subscription only | One universal spend row is sufficient. Shows declared cost and its reported/calculated/allocated basis. Requests, tokens, readiness, efficiency and unit cost remain unknown. No savings or utilization claim. A genuine zero bill is supported. |
| Cost and usage | Shows supplied provider/model/route cost buckets, requests, input/output tokens, cache-read/write tokens, basis and missing fields. Partial fields do not become zero totals. Amounts are declared attribution, not inferred allocations. No savings claim. |
| Cost, usage and complete outcomes | Calculates provider cost per ready result for a declared complete matching workload/period. Known request mismatches withhold unit cost. Missing request counts are explicitly unreconciled, not treated as a mismatch or zero. Full operating unit cost additionally requires recorded human minutes, hourly rate and shared cost. No ready results means unavailable unit cost, not division by zero. |

The single-bill path uses `baseline` on all rows; customers delete both example rows before entering an invoice. The interface documents every supported field and tells customers to aggregate to the bill boundary when usage cannot be reliably joined to model costs. PDFs, screenshots and arbitrary raw provider files are not supported. Invoice dates are not represented as proof of service-period duration. Users declare matching service-period coverage before outcome calculations.

Comparison remains a separate existing path with its matching-period, workload, currency, cost-basis, coverage, quality and policy gates. A single-bill review never claims savings, even with complete outcomes.

Saved single-bill JSON retains the supplied CSV rows (including result IDs); the interface tells users to keep it private. The new versioned format is deeply validated and recalculated on reopen, rather than trusting saved derived claims. Import also bounds the serialized JSON to 5 MiB so an exported review can be reopened under the same limit.

Regression cases cover all three levels; blank provider/model/route; zero cost and zero requests; partially reported usage; calculated/allocated bases; missing human minutes/rate/shared costs; zero ready results; incomplete logs; missing and mismatched request counts; duplicate spend/result IDs; invalid dates; negative/non-finite costs; invalid retries; mixed periods; malformed nested saved data; required-field deletion; JSON round trips; and rendered bill/memo evidence boundaries. The standalone build now embeds every occurrence of each template download, including the new path.

Chrome follow-up: the local setup was visually inspected at 1440×1000 and 390×844. No page/dialog horizontal overflow was measured. Escape closed the dialog and returned focus to Start a review; no console errors were reported. This does not establish a full keyboard focus-loop pass. File selection was blocked by the extension's file-URL permission, so browser import, result-screen screenshots and browser JSON round trips remain pending. The local test server was stopped after inspection.

## Compatibility and scope

Older non-illustrative saved comparisons without individual route periods are rejected with a rebuild instruction; their comparison duration cannot be verified. Unsupported zero-total/sub-micro-unit comparisons are rejected rather than rendered with non-finite ratios. The single-bill path supports zero cost and withholds unit cost for zero ready results. The new validator validates structure and arithmetic, not the authenticity of user-supplied evidence.

No redesign, new AI service, external upload, or unrelated feature was added. The canonical checkout and its eight untracked duplicate files remain outside this worktree.
