OpenAI sources: [pricing](https://developers.openai.com/api/docs/pricing), [model details](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [September 29 release](https://developers.openai.com/api/docs/changelog), and [data residency](https://developers.openai.com/api/docs/guides/your-data).

GPT-6.1 Sol permits 922,000 input tokens and 128,000 output tokens in a 1,050,000-token context. At **272,000 input tokens**, short-context rates apply. Above that count, the entire request uses 2x input/read/write rates and 1.5x output rates, including cached input in the threshold. Mode and geography multipliers compose. Global, US and EU processing are represented; US/EU add 10% to every token category. EU supports Standard, Batch and Flex, not Fast. The model has no published Ultrafast rate. The pricing page also states a 10% FedRAMP uplift, but this catalog does not infer FedRAMP model eligibility or offer that endpoint as a route.

Anthropic sources: [model details and release](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [pricing](https://platform.claude.com/docs/en/about-claude/pricing), and [data residency](https://platform.claude.com/docs/en/manage-claude/data-residency).

Sonnet 5.5 has a 1M-token context and a normal 128K output limit. Its full context uses the same token rates. Batch halves input/output and cache charges; the Batch cache values above are derived using the documented stacking rules. Global processing is the default; `inference_geo: us` adds 10% to all token categories. Fast, Flex, Priority and EU inference are not priced. The opt-in 300K-output Batch beta, partner-operated cloud endpoints, subscriptions and server-side tool charges remain outside the calculator's scope.

The new model effective dates follow their documented launches. The catalog-level September 22 lower bound and retained model-specific lower bounds remain historical coverage boundaries, not invented release dates. Snapshot selection uses the latest version available on the selected date; callers can explicitly use the current snapshot to price the new models from their documented release dates. Every new model rejects pre-release dates in prompt estimates and request-log calculations.
